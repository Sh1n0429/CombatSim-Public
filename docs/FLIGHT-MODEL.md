# 飛行モデルと制御の根拠

本書は航空機・ミサイルの運動、制御入力の扱い、シミュレータ独自の調整を説明します。運動計算は空力モデルに統一しています。定速モードは提供しません。
調整値は転記せず、[空力設定](../configs/aerodynamic.json)と[設定の優先順位](REFERENCE.md#設定の参照先)を参照します。

本シミュレータの諸元・運動モデル・制御処理は、航空力学・大気モデル・制御理論に関する参考情報に基づいて実装しています。簡略化や改変を加えた部分は、シミュレータ内の運動・状態遷移・時間刻みの整合性に基づき調整しています。
本書では、その基礎となる式・考え方を説明する文献を各処理に対応づけ、参考情報に基づく部分と本シミュレータで調整した部分を示します。

## 実装と文献の対応

|---|---|---|
| 揚力・抗力 | 動圧、面積、係数の積を使う形式はNASAの説明と一致する | 文献[A][B]、`motion.py` |
| 航空機の誘導抗力 | 揚力係数の二乗に比例する項を使う形式はNASAの説明と一致する | 文献[C]、`AerodynamicAircraftMotion.acceleration` |

## 共通の運動モデル

位置と速度を持つ質点として運動を計算します。航空機のheadingとpitchは速度方向を表します。機体姿勢、迎角、角運動量、舵面の動きを独立した状態として積分する剛体モデルではありません。
内部の運動計算ではSI単位へ変換し、結果をゲーム座標へ戻します。`aero_length_scale`は距離の換算、`aero_tick_seconds`はtickの秒換算、`aero_substeps`はtick内の積分分割を定義します。

動圧をq、密度をρ、速さをV、基準面積をSとすると、実装は次の形式を使います。

- q = ρ V² / 2
- 揚力 L = q S CL
- 抗力 D = q S CD

揚力・抗力は、NASAの資料にも示される動圧・基準面積・係数による式に基づいて計算します。係数と面積は、シミュレータの諸元として設定しています。[NASA: Lift Equation][A]、[NASA: Drag Equation][B]。

航空機は速度に垂直な揚力と、速度方向の推力・抗力、鉛直下向きの重力を合成します。ミサイルも推力・抗力・重力を計算しますが、方向変更とその損失には独自の処理を用います。

## 大気と航空機の推力

`density`は下層の温度低下と、その上の等温層への連続接続を使います。圧力と温度から密度を求めます。負の高度は海面高度として扱います。
大気モデルは、高度別の温度・圧力から密度を求める層別大気の考え方に基づいています。この考え方はNASAの教育用大気モデルでも説明されています。本実装では、定数の選び方と上層の接続をシミュレータのモデルとして定義しています。気象・湿度・風は計算対象に含めていません。[NASA: Earth Atmosphere Model][D]。

航空機の推力は、基準推力に密度比のべき乗を掛ける教材独自の補正です。`aero_thrust`と`aero_thrust_density_exponent`がその設定です。エンジンの実測推力マップや燃料消費モデルは使っていません。密度による推力変化を取り込むため、シミュレータの整合性に基づいて簡略化した補正式です。

## 航空機の諸元と設定値の位置づけ

航空機の諸元は、戦闘機に関する参考情報と飛行力学の考え方に基づき、質点モデルとシミュレータの整合性に合わせて設定しています。公開諸元の比較資料として、米空軍のF-16およびF-16Cのファクトシートを参照できます。機種・型式・搭載状態・推力の使用条件を区別して扱います。[米空軍: F-16 Fighting Falcon][G]、[Shaw AFB: F-16C Fighting Falcon][H]。

現在の設定一式を特定型式のF-16諸元と同一とは扱いません。特に、一定質量・基準推力・荷重上限は本シミュレータの設定であり、空虚重量・最大離陸重量・公表最大推力・実機の運用制限をそのまま代入したものとは区別します。

| 設定項目 | 意味・単位 | 参考情報に基づく部分とシミュレータでの調整 |
|---|---|---|
| `aero_mass` | 質点の一定質量（kg） | 航空機の質量という物理量に基づく設定。燃料・搭載物による変化を省略し、代表質量として使用。公開重量との比較資料は[G][H] |
| `aero_wing_area` | 揚力・抗力の基準翼面積（m²） | 揚力・抗力式の基準面積に基づく設定。翼幅とは別の量。[A][B]と翼形状の説明[I]を参照。現在値の採用元となる個別機体の面積資料は本書では特定していない |
| `aero_thrust` | 密度補正前の基準推力（N） | 推力を力として与えるモデル。開発中の挙動確認とユーザー調整を反映した設定。公表最大推力をそのまま使用した値ではない。比較資料は[G][H] |
| `aero_thrust_density_exponent` | 推力の密度補正指数（無次元） | 高度による推力変化を簡略化し、シミュレータの整合性に基づき調整 |
| `aero_cd0` | 基礎抗力係数（無次元） | 抗力係数モデルに基づく調整値。個別機体の風洞・飛行試験データとは対応づけていない。[B][C] |
| `aero_induced_drag` | 誘導抗力項の係数（無次元） | 揚力係数の二乗項に基づく調整値。翼形状からの自動算出は行わない。[C] |
| `aero_cl_max` | 揚力係数の上限（無次元） | 揚力式に上限を設けるモデル。速度・姿勢による揚力限界を簡略化した設定。[A] |
| `aero_max_load` | 揚力による荷重上限（標準重力加速度の倍数） | 運動計算の上限として設定。実機の全飛行領域の運用制限を表す値ではない |
| `aero_max_bank` | 揚力配分のバンク角上限（rad） | 横方向と上下方向の配分を制約するシミュレータ用設定。機体のロール応答は独立に積分しない |
| `aircraft_speed` | ゲーム座標での初期速度（距離単位/tick） | 初期条件として設定。最高速度・巡航速度の上限ではない。SI速度への換算には距離とtickの設定を使用 |
| `turn_rate`・`pitch_rate`・`max_pitch`・`pitch_error_scale` | 角度指令の応答・範囲 | 比例制御と指令制約に基づき、判断周期・運動計算との整合性に合わせて調整。[E] |

数値の確認先は[空力設定](../configs/aerodynamic.json)と[省略時の基礎設定](../configs/environment-defaults.json)です。機体別の上書きがある場合は、そのシナリオの`aircraft[].performance`を優先します。これらの値は教材の諸元であり、文献の掲載値そのものかどうかは項目別に判断します。

## 航空機の制御

角度誤差から旋回・上下方向の指令を作ります。非飽和域では誤差に比例し、範囲外では指令を飽和させます。この意味で飽和付き比例制御です。積分項・微分項を備えたPID制御ではありません。この処理は比例制御の考え方に基づき、指令の上限・下限を加えています。比例項の説明はMathWorksの資料を参照してください。[MathWorks: Baseline PID Controller Design][E]。

指令を実現するための揚力要求は、動圧と最大揚力係数、荷重上限、バンク上限で制限します。したがって目標角度を指示しても瞬時にその角度へ変更されるわけではありません。上下方向の指令と横方向の旋回要求の配分は独自処理です。実機の操縦装置を再現したとは位置づけません。

抗力係数は、基礎抗力に揚力係数の二乗に比例する項を加えます。この処理はNASAの資料にも示される誘導抗力の形式に基づいています。本実装では`aero_induced_drag`を設定値として使い、翼形状から自動算出しません。[NASA: Induced Drag Coefficient][C]。

## ミサイルの運動と状態管理

ミサイルは質点として扱い、機体姿勢や舵面応答を独立して計算しません。追尾情報の有無は環境が管理し、運動処理へ渡します。追尾情報がなくても推力・抗力・重力による運動は継続します。

推進は時間区間に応じて推力を切り替えるモデルです。段階の境界で積分区間を分割し、区間をまたいだ推力の適用を避けます。燃焼終了と、ゲーム上の寿命による消滅は別の処理です。設定時間は実在する製品の燃焼時間を表しません。

方向変更には上限を設け、方向変更に伴う減速も別途適用します。この減速処理は航空機の誘導抗力式と同一ではありません。具体的な追尾方式の性能や実機との等価性は、本書では検証済みとしません。

## シミュレータの整合性に基づく調整と役割

| 処理 | 実装上の役割 | 設定・参照先 | 文献との関係 |
|---|---|---|---|
| 角度誤差のスケールと飽和 | 小さな誤差では小さな指令を生成し、指令範囲を制限する | `pitch_error_scale`、`pitch_rate`、`turn_rate` | 比例制御に対応するが、設定値は独自 |
| 後方目標への旋回方向の保持 | 角度の折返し付近で、近接する目標への旋回側を保持する | `FlightControl.stabilized` | 独自の状態保持処理 |
| 揚力要求の配分 | 上下方向と横方向の要求を制約内へ収める | `AerodynamicAircraftMotion.acceleration` | 配分規則は独自 |
| 推力の密度補正 | 高度に伴う推力変化を簡略的に表現する | `aero_thrust_density_exponent` | 独自モデル |
| 追尾復帰の確認期間 | 断続的な捕捉だけでは復帰状態へ移らないようにする | `missile_reacquisition_confirm_ticks`（tick） | 独自の状態遷移条件 |
| 復帰時のランプ | 復帰直後に制御割合を全量へ戻すことを避ける | `missile_reacquisition_ramp_seconds`（秒） | 上昇時はレート制限と対応 |
| 方向変更に伴う速度損失 | 旋回に追加の速度損失を与える | `aero_missile_turn_drag` | 独自の損失モデル |
| 積分の分割 | tick内でも力を再計算する | `aero_substeps` | 数値計算上の分割。設定だけでは精度保証にならない |

復帰ランプは、追尾を失うと割合をリセットし、復帰後は上限まで一定の速度で増加させます。上昇部分はMathWorksのRate Limiterが示す一定勾配の更新と対応します。ただし、喪失時のリセットと復帰判定を含めた全体は本シミュレーター独自の状態機械です。一般的な両方向レートリミッタそのものではありません。[MathWorks: Rate Limiter][F]。

ここでいう整合性は、運動計算と制御指令、状態切替、時間刻みの扱いを一貫させることです。各調整はこの目的で適用しています。数値精度や実機性能に対する評価は、対象条件を定めた誤差評価・収束確認・実測との比較によって別途扱います。

## ルールベース方策の根拠

[ルールベース方策](../combatsim/policies.py)は、状態を保持して行動を切り替えるゲームAIと、目標方向へ進路を向ける操舵の考え方に基づいて構成しています。状態管理の参考文献はNystromのState、行動選択・操舵・移動の分離の参考文献はReynoldsのSteering Behaviors for Autonomous Charactersです。[Nystrom: State][J]、[Reynolds: Steering Behaviors][K]。

本実装では機体ごとの記憶と優先順位付きの条件分岐を使用します。状態ラベルに加えて、継続時間や直前の目標などを保持します。そのため、有限状態機械に基づく状態管理として説明できますが、文献のStateパターンのクラス構成をそのまま採用した実装ではありません。

Reynoldsの行動選択・操舵・移動の分離に対応して、`RulePolicy`が目標方向と離散行動を選び、環境が行動を解釈し、運動モデルが位置・速度を更新します。Reynoldsのステアリング力をそのまま積分する構成ではなく、角度指令と空力制約に合わせて改変しています。

| 実装上の処理 | 基礎となる手法・参考文献 | シミュレータの整合性に基づく調整 |
|---|---|---|
| 機体別の状態と履歴の保持 | 状態に応じて処理を切り替えるゲームAI [J] | 状態ラベル、継続時間、直前目標を辞書で管理 |
| 目標方向への追従 | 目標への操舵であるseekの考え方 [K] | 相対方位・仰角から角度指令を作る。未来位置を予測するpursuitとは区別 |
| 巡回地点の切替 | 経路に沿った移動・目標追従 [K] | 地点への到達を判定して次の地点へ切替。文献の連続的な経路追従式そのものは使用しない |
| 空域境界からの復帰 | 領域内へ戻すcontainmentの考え方 [K] | 空域内側への指令と、進入・解除条件を分ける履歴依存の判定 |
| 目標高度への追従 | 比例制御 [E] | 高度誤差を制限付きの角度指令へ変換 |
| 行動の優先順位 | 行動選択と操舵を分ける構成 [K] | 観測と記憶に応じて、そのtickに使う指令を選択 |

境界復帰、追従、距離調整、警報への反応、支援継続などの具体的な条件は本シミュレーターのルールです。状態の優先順位、継続期間、距離・角度の閾値を、引用文献が定めた値として扱いません。これらは観測契約、判断周期、空域、運動モデルの整合性に基づいて調整しています。

ルール方策は環境が渡した観測を用いて判断します。観測の生成や捕捉条件は環境側の責務です。飛行指令と射撃判断は別々に計算し、最終的な行動の適用条件は環境と共有します。この役割分担は本シミュレーターの実装上の契約です。

### fixとrandom

`fix`は設定されたパラメータを固定して使用します。`random`は指定範囲からエピソードごとにパラメータを抽選し、その試合中は保持します。両者の行動ロジックは共通です。この抽選と混合率の設計は、学習相手に変動を持たせるための教材用の構成です。

[省略時のルール設定](../configs/rule-defaults.json)、[fix・randomの差分と抽選範囲](../configs/scenario-rule-curriculum.json)、[通常学習の混合率](../experiments/default.yaml)を参照してください。値は設定ファイルを正とし、文献や本文へ重複して転記しません。

## 確認の範囲と再現性

参考情報に基づく実装と、シミュレータの整合性に基づく調整の対応を、ソースコードと公開資料の照合によって確認しています。確認対象は、式・処理の対応と実装上の動作です。
既存の回帰検証には、推進区間の切替、追尾なしの運動、接地処理、復帰状態の伝達、高速化経路との一致などがあります。これは記載された条件で実装の契約を確かめるもので、飛行領域全体の精度や安定性を保証する試験ではありません。

再現にはモデル・設定・実装の版を合わせて保存します。条件比較では、変更する要因を明示し、それ以外をそろえます。
